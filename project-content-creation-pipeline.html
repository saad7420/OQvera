Content Creation Pipeline using LangGraph.

A graph-based, quality-controlled content generation system that moves from a topic through research, outlining, drafting, editorial evaluation, revision, and publishing. Instead of treating content creation as one prompt, the system models the process as a stateful workflow with explicit stages and a conditional quality gate.

How the system works

The pipeline uses LangGraph to coordinate specialized workflow nodes over a shared state. Each stage reads the information produced by previous stages and returns only the state fields it updates. After drafting, a structured evaluator scores the post and provides editorial feedback. Drafts below the quality threshold are sent back through revision.

Quality gate

The editorial evaluator returns a structured score, feedback, and pass/fail signal. The routing logic uses a score of 7/10 as the publication threshold.

  • Score ≥ 7: publish the current draft.
  • Score < 7: revise using the editor feedback.
  • Maximum revisions: 2, preventing an infinite loop.
  • History: every draft and its feedback are preserved.

Pipeline stages

01
Research

Generates key insights, facts, trends, and talking points for the supplied topic.

02
Outline

Transforms the research notes into a structured and engaging blog outline.

03
Draft

Produces the first complete article and initializes the revision history.

04
Review

Uses structured output to score quality and generate actionable editorial feedback.

05
Revision

Rewrites the draft using the latest feedback, increments the revision count, and records the result.

06
Publish

Formats the accepted draft into the final post with the topic as its title.

Technology stack

The implementation is intentionally lightweight: LangGraph handles orchestration and state, LangChain handles prompt/LLM composition, Groq provides the LLM runtime, and Pydantic defines the structured evaluation contract.

Graph design

START → Research → Outline → Draft → Review → Quality Gate. The gate routes either to Revision and back to Review, or to Publish and then END.

Example batch

The supplied implementation demonstrates the workflow against three topics, making it useful as a reusable foundation for programmatic content generation rather than a single hard-coded post.

Scope & Business Value

Scope & Benefits of the Pipeline

The pipeline is designed as a reusable foundation for structured AI content operations. Its scope goes beyond generating a single article: it establishes a repeatable orchestration layer in which research, planning, generation, evaluation, revision, and publishing are explicit and independently extensible components.

01 / Input

Topic-driven generation

Accepts a topic as the primary workflow input and propagates it through the complete content lifecycle without manually coordinating intermediate prompts.

02 / Research

Research synthesis

Produces research notes containing insights, facts, trends, and talking points that become contextual input for downstream generation.

03 / Planning

Content architecture

Separates outlining from drafting so the generation process establishes a coherent information structure before expanding it into the article.

04 / Generation

LLM-based drafting

Uses Groq-hosted Llama 3.3 70B through ChatGroq to transform outline and research context into a complete first draft.

05 / QA

Automated quality control

Applies a dedicated evaluator with structured output, creating a measurable quality gate rather than treating the first response as final.

06 / Recovery

Bounded revision loop

Automatically routes weak drafts back into revision and review while enforcing a maximum of two revision cycles.
